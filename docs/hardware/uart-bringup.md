# UART phase 1: Flash and test (cross-board HELLO/STATUS/TEXT confirmed)

**Bench result (2026-10-26):** S3 GPIO47↔GPIO21 direct UART loopback passed (self-received `HELLO` and `ACK`); LILYGO GPIO6↔GPIO1 direct UART loopback passed (`TX: TEST_18`/`RX: TEST_18` through at least TEST_22). The previous GPIO4↔GPIO5 jumper yielded TX-only output and is retired. Loose/unsoldered header contact was the root of missing C5 RX on the test rig. **End-to-end UART is now confirmed:** S3 Serial Monitor received true C5 HELLO, LOG and repeated STATUS frames (`lcd=1;ble=1;wifi=1;soc=100`). S3 console `msg Hello from Brain` correctly changed the LILYGO screen. Physical UART used the GPIO47/21 ↔ C5 GPIO1/6 mapping shown below; both boards on separate USB supplies with common GND. Ensure solid electrical header contacts before connecting the boards.

**Power:** Keep both boards on **separate USB-C supplies**; remove the 5V/5V jumper before attaching both USB inputs. Verify printed pin labels and use three wires: **S3 GPIO47 TX → C5 GPIO1 RX**, **C5 GPIO6 TX → S3 GPIO21 RX**, and **GND → GND**. Do not connect 5V to 5V or 3V3 to 3V3. Both MCU GPIOs are 3.3V logic. When only one board is powered, unplug signal wires to avoid I/O backfeeding.

**Flash:** Disconnect UART wires for individual uploads. S3: open `firmware/CuteDisplayBrain/CuteDisplayBrain.ino` with `BrainPinPlan.h` and new `CuteLink.h` in the same sketch folder. Choose ESP32S3 Dev Module, 16MB flash, OPI PSRAM; connect USB-UART for uploading and monitoring. C5: open `firmware/CuteDisplay/lcd.ino` with its new `CuteLink.h`, working `board_config.h`, LILYGO AXP2602 library; choose ESP32C5 Dev Module, 16MB flash, QIO PSRAM.

**Test:** Power both independently, connect 3 wires, open S3 Serial Monitor **115200 baud, Newline**. Expect `[S3] C5 UART connected`, `[C5] ... HELLO`, `[C5] ... STATUS`. Type `help`, `status`, `ping`, `battery`, `msg Hello Kitty`, `mood 1`, `mascot 1`. Text commands currently allow **ASCII only** (1–80 bytes); Japanese glyph transfer is future work. Keep the iPhone app separate during test to avoid conflicting display changes.

**Protocol:** `@CD1|seq|type|payload|CRC8\n` (CRC8 polynomial 0x07 over `CD1|seq|type|payload`), 160-byte max frame and 96-byte payload, HELLO/ACK, selected C5 status/voltage/battery current reports, periodic status every 5s, 10s link timeout. No retries, ACK tracking, UTF-8 glyph chunks, or complete forwarding of historical C5 USB Serial logs. Early C5 boot logs still require its own USB monitor.

**Migration status:** S3 BLE diagnostic service remains unconnected to iPhone control. C5 retains current iPhone BLE, LCD, battery and Wi-Fi logic. I2S, AI, camera, relay BLE services and single-USB power capacity remain untested. The *separate loopback sketches* have passed individually. The pin-updated integrated firmware has been flashed and confirmed for HELLO, C5 STATUS telemetry and one message command. Retest any new protocol changes before calling the link reliable under resets, extended runtime or heavy network/audio load.

**Later:** The user reports a working S3-only USB power boot with 5V header sharing and UART still functional, but the current rating/backfeed path remain unverified. A limited opt-in BLE relay was subsequently added to the S3 firmware (source not tested yet): [Phase 2 test](ble-relay-test.md).

## Updated Phase 4 link settings (historical UART steps above are for earlier firmware)

**New firmware on both boards:** `921600` baud, GPIO pair unchanged. The previous 115200 value in old test screenshots/source snippets applies only to older builds. **USB Serial Monitor remains at 115200 baud**, regardless of the UART connection speed. Persistent Brain disconnected popup is documented in [Phase 4 bench guide](brain-link-921600.md). With a power/boot/baud mismatch on either board, the C5 displays the popup until both boards run compatible UART firmware.
